Standing risks

▲
b22f06b is unverified, in the same narrow sense b6a6a5b was. xcrun swiftc -parse passed on both changed files, but kindbook has no iOS SDK — that is syntax only, with no type checking and no isolation analysis. The same class of reasoning-plus-parse held up under a real compiler last time; that is one data point, not a method.
▲
Expect more errors, and don't read them as trouble. The compiler surfaces one at a time on a fresh tree, so each fix buys one more file's worth of visibility. "Another error" is progress through the file list, not a widening problem.
▲
Calibration is Codable and nothing persists it. Not a compile error — the user simply recalibrates from scratch on every cold launch. Someone made it storable and no one stored it. Folded into the HomeView work rather than fixed inside a build patch.
▲
The fleet has exactly one signing path, and it expires Aug 2027. One Job's two cached profiles are the only thing letting anything on Amber archive, and nothing would surface their lapse until it happened. Not urgent; should not be invisible.
▲
The 24 Nov date has not been re-verified since the original notice — Apple's mail doesn't reach any mailbox an agent reads. Item 02.
▲
Apple has rejected this app once before — July 2023, specifically over background modes. 2.0 omits UIBackgroundModes deliberately, but expect scrutiny there.
▲
Age-rating social-media questions must be answered at submission. A gate, not a deadline; the answers are "no" across the board. Ten minutes in App Store Connect.

Method notes

three worth keeping
The first error hid the second, and that is worth expecting rather than rediscovering. Clearing LiveMicSource:37 immediately surfaced CalibrationView:127, which would have failed identically before the first fix — the compiler had simply stopped short of the view. On a tree that has never compiled, the honest forecast is "more errors, serially," not "nearly there."
A compile error is not always a concurrency error. Both suspects I had reasoned about were actor-isolation stories; the second error was plain access control, with no notes and no diagnostics attached. Reading private(set) as an invariant rather than an obstacle is what picked the fix — and the fix was a design decision the compiler had no opinion about.
Pard corrected himself twice in two days, both the same shape: reporting the state of his machine as the state of the world — the pre-Xcode-16 profiles directory, then an uncommitted project.yml. git show HEAD:<file> before trusting any "I set X" is now a standing check, and it applies to me at least as much as to him.
